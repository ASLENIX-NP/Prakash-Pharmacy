\section{Executive Summary \& Project Mission}

The \textbf{Prakash Pharmacy Management System (PMS)} is an enterprise-grade, integrated retail pharmacy, wholesale inventory, customer credit, and outpatient clinic management solution designed specifically for the community pharmacy environment in Nepal.

The primary objective of this project was to engineer a fast, fault-tolerant, modern web-based application that replaces manual paper records and generic software with a purpose-built system complying with:
\begin{enumerate}
    \item \textbf{Department of Drug Administration (DDA) Regulations:} Batch-level traceability, expiry warnings, narcotic and psychotropic drug classification, prescription enforcement.
    \item \textbf{Inland Revenue Department (IRD) Tax Policies:} Sequential tax invoices, 13\% Value Added Tax (VAT) computation, VAT-exempt medicine accounting, sales registers, and credit notes.
    \item \textbf{Nepalese Pharma Commercial Realities:} Dual packaging models (converting bulk packs/strips to loose tablets with automatic fractional pricing), distributor bonus goods (\textit{Free/Bonus Packs}), and running customer credit accounts (\textit{Udharo/Khata}).
    \item \textbf{Integrated Polyclinic Workflow:} OPD appointment queue, patient demographic records, vital sign tracking, and digital prescription creation flowing directly into the POS dispensing queue with zero double-entry.
\end{enumerate}

\subsection{Current Project Health \& Operational Readiness}
As of \textbf{November 5, 2026}, \textbf{100\% of application features, UI panels, business services, database tables, and API routes have been built, integrated, and verified}. Static type checking passes cleanly with zero errors on both the frontend React client and the backend Express server. The production bundle builds in 539 milliseconds with zero compiler warnings.

The production database has been wiped clean of all development and dummy transactions using safe cascading truncate routines, resetting invoice and credit note counters back to initial baseline. \textbf{The single remaining phase is deploying the repository to the production host (Render).}

\subsection{Unified Single-Service Fullstack Deployment Mode}
A key architectural innovation in Prakash Pharmacy is its \textbf{Unified Single-Service Architecture}:
\begin{itemize}
    \item When running on Render, the backend server inspects the runtime environment and dynamically detects the compiled frontend directory (\texttt{frontend/dist}).
    \item Express serves the backend REST API on \texttt{/api/*} while simultaneously serving the optimized Single Page Application (SPA) static bundle for all client routes (\texttt{/*}).
    \item \textbf{Operational Benefit:} Eliminates cross-origin resource sharing (CORS) complexity, avoids cold-start latency across separate services, and enables running both frontend and backend under a single unified URL on Render's free or standard tier.
\end{itemize}

\subsection{Database Integrity \& Cascading Safety Rules}
\begin{itemize}
    \item \textbf{Transaction Atomicity:} When an invoice is processed at POS, the creation of \texttt{Bill}, insertion of all \texttt{BillItem} rows, deduction of stock from \texttt{Inventory}, and posting to customer \texttt{Ledger} execute inside a single atomic Prisma transaction (\texttt{prisma.\$transaction}). If any step fails, the entire operation rolls back.
    \item \textbf{Preventing Orphaned Financial Records:} Sales returns and purchase invoices use restricted deletion policies (\texttt{ON DELETE RESTRICT}) to prevent accidental deletion of historical tax records.
\end{itemize}

\section{Deep Functional Audit of Completed Modules}

Every functional requirement specified for Prakash Pharmacy has been built, hardened, and verified.

\subsection{Module 1: Authentication, Authorization \& Multi-Tier RBAC}
\begin{itemize}
    \item \textbf{4 Distinct Roles:} \texttt{ADMIN} (Full system control, profit margins, settings), \texttt{PHARMACIST} (Drug catalog, inward stockists, dispensing), \texttt{CASHIER} (POS billing, returns, customer credit collection), and \texttt{DOCTOR} (Clinic OPD queue, patient vitals, digital prescription writing).
    \item \textbf{Stateless JWT Verification:} Tokens signed with \texttt{HS256} algorithm, verified by Express middleware with automatic expiration and refresh checks.
    \item \textbf{Administrative Password Security:} Passwords hashed with BCrypt (10 salt rounds). Staff management view supports adding, updating, and deactivating staff.
\end{itemize}

\subsection{Module 2: Inventory, Batch Tracking \& DDA Regulatory Control}
\begin{itemize}
    \item \textbf{Dual Pack and Loose Unit Engine:} Supports selling full boxes/strips or individual loose tablets. When a strip is opened, the system decrements pack stock and increments loose units. Unit selling price is automatically calculated as $\text{MRP} / \text{UnitsPerPack}$.
    \item \textbf{FEFO Batch Prioritization:} The system automatically prioritizes the batch with the earliest expiration date to minimize shelf obsolescence.
    \item \textbf{Visual Expiry Alerts:} Real-time visual status badges:
    \begin{itemize}
        \item \colorbox{RoseLight}{\textbf{\color{RoseDanger}Expired:}} Date has passed. Selling is blocked.
        \item \colorbox{AmberLight}{\textbf{\color{AmberWarning}Near Expiry ($\le$ 30 Days):}} Critical alert for immediate dispensing or return to distributor.
        \item \colorbox{AmberLight}{\textbf{\color{AmberWarning}Expiring Soon ($\le$ 90 Days):}} Warning banner for priority clearance.
        \item \colorbox{EmeraldLight}{\textbf{\color{EmeraldSuccess}Safe Stock:}} Standard active inventory.
    \end{itemize}
    \item \textbf{DDA Regulatory Tags:} Explicit flags for \textbf{Prescription Required (Rx)}, \textbf{Narcotic / Psychotropic}, and \textbf{Schedule Drugs}.
    \item \textbf{Distributor Scheme Bonus Tracking:} Tracks free bonus packs (\texttt{freePacks}) received from distributors without artificially lowering baseline unit cost.
    \item \textbf{Shelf \& Rack Management:} Medicines assigned to physical locations (e.g., \textit{Rack A-2}, \textit{Fridge}, \textit{Counter Shelf}).
\end{itemize}

\subsection{Module 3: Point-of-Sale (POS) Billing \& IRD Tax Invoicing}
\begin{itemize}
    \item \textbf{High-Speed Search:} Sub-second fuzzy search across brand names, generic molecules, and barcode scans.
    \item \textbf{Batch Selection Modal:} Cashiers can explicitly pick alternate batches if a customer requests a specific batch or expiry date.
    \item \textbf{Multi-Tender Payments:} Supports Cash, Credit Card, Fonepay / QR Code, Customer Credit (\textit{Udharo}), and Split Payments.
    \item \textbf{Sequential Tax Invoices:} Automatically increments \texttt{nextInvoiceNumber} and prints compliant tax invoices complete with store PAN, buyer details, and itemized VAT breakdowns (compatible with 80mm thermal rolls and standard A4 printers).
\end{itemize}

\subsection{Module 4: Sales Returns, Credit Notes \& Automatic Restocking}
\begin{itemize}
    \item \textbf{Seamless Returns:} Returns can be initiated from historical invoice search or entered as ad-hoc counter returns.
    \item \textbf{Automatic Restocking:} Returned medicines are automatically added back to active inventory with correct batch and unit counts.
    \item \textbf{Sequential Credit Notes:} Generates official credit notes with dedicated numbering (\texttt{next\_credit\_note\_number}).
    \item \textbf{13\% VAT Reversal:} Accurately reverses the VAT liability for returned taxable goods.
\end{itemize}

\subsection{Module 5: Customer Credit (Udharo / Khata) Ledger}

    \item \textbf{Customer Khata Directory:} Customer profiles with phone numbers, addresses, and customizable credit limits.
    \item \textbf{Automatic Ledger Debits:} Selecting \texttt{Credit} at POS automatically posts a debit entry to the customer's ledger.
    \item \textbf{One-Click Payment Settlement:} Cashiers can log partial or full cash/QR payments against outstanding customer balances.
    \item \textbf{Ledger Statement Export:} Comprehensive transaction history with running balances available for customer viewing.
\end{itemize}
